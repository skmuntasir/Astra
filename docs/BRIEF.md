# ASTRA v2 — BRIEF (the permanent spec)

> This file is the product spec. It changes only when the product changes, never to match the code.

## The product

One continuous scroll journey where **the camera never cuts and nothing repeats.**

**Earth** (large, like a hero) → **Moon** → **Sun** → **Solar System**. Planets are clickable; clicking flies the camera to that planet, shown large and beautiful like the Earth hero, with an info panel, and **Back returns to the exact scroll position**.

Then the journey continues out: **nearby stars → Milky Way → Local Group → nearby galaxies → a black hole (M87\*)**, where a choice appears: **"Fall into the black hole?"**

- **Yes** = a super-realistic, scroll-driven infall (an optional sub-timeline that returns to the main path).
- **No** = continue → **cosmic web → observable universe → multiverse** (clearly labelled as speculative).

Movement between objects must be very smooth with scroll. **Every object in every zone is loaded BEFORE the journey starts** (a loading screen with real progress), so scrolling never waits.

### Not part of this product

The old project's long late chapters (Observatory, Star Map, Deep Space, Search for Life, Humanity, Stars, Milky Way, Galaxies, Universe, Cosmic Scale) and anything about habitable planets. They are not ported and must not be re-added.

## Image policy

- The user supplies no textures.
- Earth (day / night / clouds / ocean) and Moon albedo come from the old project's `src/assets` (NASA-derived; the credit-needed flag is kept in `ASSETS.md`).
- Every other image is **procedurally generated by code in `tools/texgen`, never downloaded.**
- The network may be tried once for real NASA textures; if it fails, never retry or block.

## Non-negotiable engine rules

1. ONE R3F Canvas, mounted once, never unmounted.
2. One master timeline: scroll → target progress `t` → critically-damped smoother → keyframed camera path per zone with eased joins. The camera never jumps.
3. Zones live in a registry (`src/engine/journey.ts`); adding a zone never touches the engine. Objects of inactive zones are `visible=false`, never unmounted, never disposed.
4. Scale from 1 Earth radius to ≥ 1e10 units is handled by floating origin (camera-relative, double-precision placement), logarithmic depth, per-zone unit systems.
5. Everything is preloaded and uploaded to the GPU (and every shader compiled, one warm-up frame per zone) before the journey starts. Texture budget ≤ 60 MB on desktop; mobile tier 2k max.
6. Quality tiers high / medium / low (auto + manual), DPR cap, and a reduced-motion mode (cross-fade between stills, no pinned camera).
7. HUD: zone title, scale readout in real units, progress rail with clickable zone ticks (far jumps cross-fade instead of flying through everything), keyboard accessible.
8. Hooks: `focus(objectId)` / `release()`, and the `choiceGate` API for branching sub-timelines.
